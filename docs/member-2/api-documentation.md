# FlexiAura API Documentation (Member 2)

## Base URL

```text
http://localhost:3000
```

`PORT` is configurable in `backend/.env`.

All request and response bodies use JSON.

## Health

### GET `/health`

Checks that the backend is running and whether Gemini is configured.

Response:

```json
{
  "success": true,
  "service": "flexiaura-backend",
  "aiConfigured": true,
  "model": "gemini-3.5-flash-lite",
  "geminiKeyCount": 4
}
```

When no API key is configured, `aiConfigured` is `false`, `model` is `null` and `geminiKeyCount` is `0`.

## AI Chat

### POST `/api/ai/chat`

Sends a user message to Gemini with the FlexiAura system prompt and session context.

Request:

```json
{
  "sessionId": "session-001",
  "message": "Hello FlexiAura"
}
```

- `sessionId` is optional. If omitted, the backend creates one and returns it.
- `sessionId` must be 1-100 characters using letters, numbers, hyphens or underscores.
- `message` is required, trimmed, and limited to 4000 characters by default.

Response:

```json
{
  "success": true,
  "answer": "Hello! How can I help you today?",
  "sessionId": "session-001",
  "model": "gemini-3.5-flash-lite"
}
```

The answer is generated by Gemini. It is never a hardcoded response.

Error responses:

| Status | Code | Meaning |
|---|---|---|
| 400 | `INVALID_MESSAGE` | Message is missing or empty |
| 400 | `MESSAGE_TOO_LONG` | Message exceeds the configured limit |
| 400 | `INVALID_SESSION_ID` | Session ID has an invalid format |
| 429 | `RATE_LIMITED` | Too many requests |
| 502 | `AI_SERVICE_ERROR` | Gemini request failed |
| 502 | `AI_EMPTY_RESPONSE` | Gemini returned no text |
| 503 | `AI_NOT_CONFIGURED` | No Gemini key is configured |
| 504 | `AI_TIMEOUT` | Gemini request exceeded the timeout |

Example:

```bash
curl -X POST http://localhost:3000/api/ai/chat ^
  -H "Content-Type: application/json" ^
  -d "{\"sessionId\":\"session-001\",\"message\":\"Hello FlexiAura\"}"
```

## Reset Conversation

### POST `/api/ai/reset`

Clears the message history for a session while keeping the session ID usable.

Request:

```json
{
  "sessionId": "session-001"
}
```

Response:

```json
{
  "success": true,
  "sessionId": "session-001",
  "message": "Conversation context reset."
}
```

`sessionId` is required. A missing or invalid ID returns `400 INVALID_SESSION_ID`.

## Get Conversation History

### GET `/api/conversation/:sessionId`

Returns the stored messages for a session.

Response:

```json
{
  "success": true,
  "sessionId": "session-001",
  "messages": [
    {
      "role": "user",
      "content": "My name is Alex.",
      "timestamp": 1763570000000
    },
    {
      "role": "assistant",
      "content": "Nice to meet you, Alex!",
      "timestamp": 1763570001500
    }
  ],
  "createdAt": 1763570000000,
  "updatedAt": 1763570001500
}
```

If the session does not exist or has expired:

```json
{
  "success": false,
  "error": {
    "code": "SESSION_NOT_FOUND",
    "message": "The requested conversation session was not found or has expired."
  }
}
```

Status: `404`.

## Delete Conversation

### DELETE `/api/conversation/:sessionId`

Deletes a session and its messages.

Response:

```json
{
  "success": true,
  "sessionId": "session-001",
  "message": "Conversation deleted."
}
```

Missing or expired sessions return `404 SESSION_NOT_FOUND`.

## Voice Status

### GET `/api/voice/status`

Reports which speech providers are active. Browser-native speech does not require a backend endpoint.

Response:

```json
{
  "success": true,
  "voice": {
    "speechToText": {
      "provider": "web-speech-api",
      "mode": "browser",
      "requiresBackend": false,
      "cloudConfigured": false
    },
    "textToSpeech": {
      "provider": "web-speech-api",
      "mode": "browser",
      "requiresBackend": false
    },
    "supportedBrowsers": [
      "Chromium-based browsers with Web Speech API support"
    ]
  }
}
```

## Error Format

All API errors use the same shape:

```json
{
  "success": false,
  "error": {
    "code": "INVALID_MESSAGE",
    "message": "message is required and must be a non-empty string."
  }
}
```

Unknown endpoints return `404 NOT_FOUND`.

## Rate Limiting and Size Limits

- `/api` routes: 60 requests per minute per IP by default.
- JSON request body limit: 16 KB by default.
- Message limit: 4000 characters by default.
- Rate-limited responses return `429 RATE_LIMITED`.

These values are configurable through environment variables listed in `backend/.env.example`.

## CORS

Allowed by default:

- Origins listed in `CORS_ORIGIN` (comma-separated).
- Local development origins on `localhost` or `127.0.0.1`.
- Tauri origins `tauri://localhost` and `http://tauri.localhost`.

Requests without an `Origin` header (curl, Postman) are allowed.

## Frontend Configuration

The React frontend reads `VITE_API_BASE_URL` and defaults to `http://localhost:3000`:

```env
VITE_API_BASE_URL=http://localhost:3000
```

Copy `flexiaura-app/.env.example` to `flexiaura-app/.env` when a different backend host is needed.

## Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3000` | Backend port |
| `GEMINI_API_KEY` | none | Single Gemini key |
| `GEMINI_API_KEYS` | none | Comma-separated keys for round-robin rotation and failover; takes precedence over `GEMINI_API_KEY` |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | Gemini model name |
| `CORS_ORIGIN` | empty | Extra allowed origins, comma-separated |
| `MAX_MESSAGE_LENGTH` | `4000` | Maximum user message length |
| `MAX_HISTORY_MESSAGES` | `40` | Stored messages per session |
| `MAX_CONTEXT_MESSAGES` | `20` | History messages sent to Gemini |
| `MAX_CONTEXT_CHARS` | `12000` | History character budget |
| `SESSION_TTL_MS` | `7200000` | Session expiry (2 hours) |
| `AI_TIMEOUT_MS` | `30000` | Gemini timeout |
| `API_RATE_LIMIT_MAX` | `60` | Requests per window per IP |
| `LOG_LEVEL` | `info` | `error`, `warn`, `info` or `debug` |

Never commit `backend/.env` or any real API key.
